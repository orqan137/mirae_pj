# 연금 연구에서 도출한 Agent 설계

## 결론

현재 Agent는 제도 설명과 제공자료 검색에는 강한 기반이 있지만, 좋은 연금 Agent가 되려면
`생애 단계 판정`, `보장소득·유동성·위험의 분리`, `결정론적 시나리오 계산`이 더 필요하다.

## 1. 질문 상태 모델

```text
제도/계좌 식별
  → 생애 단계(적립·운용·이전·인출)
  → 목표(절세·보존·소득·유동성·유산)
  → 제약(기간·위험·현금수요·기존 보장소득)
  → 근거와 계산 가능성
  → 설명 또는 조건부 비교
```

`연금 추천`을 바로 상품 검색으로 보내지 않는다. 계좌와 상품을 분리하고, 수급 전·후인지,
필수지출을 충당하는 국민연금·DB·기타 종신소득이 있는지 먼저 확인한다.

## 2. 최소 suitability 입력

| 축 | 필요한 이유 | 누락 시 처리 |
|---|---|---|
| 계좌·제도 | DB/DC/IRP/연금저축 규칙이 다름 | 일반 원칙만 설명 |
| 생애 단계·예상 기간 | 축적과 인출의 위험이 다름 | 기간별 시나리오 분리 |
| 목적 | 절세, 성장, 소득, 유동성은 상충 | 우선순위 질문 |
| 위험감수·손실수용 | 수익률만으로 상품을 고를 수 없음 | 순위 추천 금지 |
| 비상유동성·부채 | 연금화·장기투자 가능성을 바꿈 | 연금화 비율 제시 금지 |
| 기존 보장소득 | 장수위험의 미충족 부분을 결정 | 필수지출 부족액 계산 보류 |
| 유산동기·건강 관련 현금수요 | 연금화와 유동성의 균형을 바꿈 | 복수 대안과 한계 제시 |

각 입력은 `stated`, `derived`, `missing`, `conflicting` 상태와 출처를 가진다. 평균 고객이나
중간 위험성향으로 누락값을 채우지 않는다.

## 3. 결정론적 도구 후보

1. 귀속연도별 납입·세액공제 계산기
2. 연금/일시금 수령 시나리오 비교기
3. 명목·실질, 누적·연환산 변환기
4. 상품 클래스·수수료·기간 정렬기
5. 적립·인출 현금흐름 프로젝터
6. 수익률 순서위험 스트레스 시나리오

계산 결과에는 필수지출 보장률, 유동자산, 적립 부족액, 고갈연령·감액, 사용한 가정과 규칙
버전을 분리한다. 일시금 선택 가능성과 연금수령 적정성을 하나의 점수로 합치지 않는다.

LLM은 입력을 구조화하고 결과를 설명하되, 세율·수식·현금흐름을 직접 산술하지 않는다.

## 4. 답변 품질 게이트

- `현재 제도`와 `정책 제안`을 혼합하지 않았는가?
- 기간말 적립금을 현재 잔고로 표현하지 않았는가?
- 과거 수익률을 보장 또는 추천 근거 하나로 사용하지 않았는가?
- 계좌와 계좌 안 상품을 구분했는가?
- 연금화의 장수위험 완화와 유동성 감소를 함께 설명했는가?
- 질문에 없는 나이·소득·건강·위험성향을 추정하지 않았는가?
- `사람/계좌/금액`, 관측연도/발표일, 판매가능/전체시장 분모를 혼합하지 않았는가?
- 제공 상품집합을 만든 사업자·계열관계·제외 범위를 중립적 전체시장으로 표현하지 않았는가?

## 5. 평가셋 도출

평가질의는 최소 다음 교차축을 포함해야 한다.

- 단계: 적립 / 운용 / 이전 / 중도인출 / 연금수령
- 제도: DB / DC / IRP / 연금저축 / 복수연금
- 요구: 규칙 / 계산 / 단일상품 / 비교 / 조건부 추천
- 함정: 기준연도 충돌 / 클래스 불일치 / 단위 불일치 / 조건 누락 / 정책제안 오인

가장 중요한 실패 테스트는 `근거 또는 조건이 없을 때 그럴듯한 숫자를 만들지 않는가`다.
