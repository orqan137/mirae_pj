# Agent action boundaries

Pension Advisor는 고객 대신 행동하는 범용 자율 Agent가 아니다. 허용된 자료를 조회하고 제한된
계산을 수행해 평가 답변을 만드는 read-mostly 질의응답 Agent다.

## 1. 허용된 행동

### 항상 허용

- 요청 schema와 문자열 계약 검증
- 질문의 연금 도메인 분류와 하위 요구사항 식별
- 검증된 주최 측 파생 코퍼스의 읽기 전용 검색
- 상품코드별 구조화 원문 근거 조회
- 허용 범위가 명시된 결정론적 계산
- 근거의 대상·날짜·클래스·단위·좌표 검사
- HyperCLOVA X를 이용한 최종 한국어 답변 생성
- 답변과 근거의 일치 여부 검사
- 비밀정보를 제외한 실행 상태·시간·문서 수 요약
- 동일 완료 응답의 로컬 캐시 저장과 재사용

### 조건부 허용

- 외부 법령·통계·공시 사용: 대회 허용, 출처 검토, 기준일 확인, 승인된 코퍼스인 경우만
- 내부 업무문서 사용: 고객에게 필요한 규칙을 이해하는 용도만; 내부 화면·코드·개인정보 제거
- 상품 추천: 다섯 suitability 조건과 계좌·위험·목적·기준일 공식 상품 근거가
  모두 있을 때 코퍼스 내 최대 3개 조건부 후보만
- 개인 계산: 계산기 계약이 요구하는 입력이 정확히 주어지고 지원 시나리오인 경우만
- 한 번의 답변 수정 생성: 별도 시간예산과 deterministic validator가 구현된 이후만

## 2. 금지된 행동

- 다른 생성 LLM 또는 모델 fallback 호출
- 운영 중 웹 검색, 뉴스 검색, 임의 외부 RAG
- 고객 계좌·잔고·거래내역·개인정보 조회
- 금융상품 가입, 주문, 매매, 이체, 해지, 이전 실행
- 사용자를 대신한 법률·세무 신고나 확정적 전문판단
- 수익률, 원금 보장, 세금 절감, 적합성을 보장
- 조건부 후보를 법적 적합성 확정·전 시장 1위·최적 상품으로 표현
- 자료에 없는 세율·한도·수익률·수수료·시장잔고 생성
- 상품코드와 판매 클래스 추정
- 서로 다른 클래스·기간·단위의 직접 비교
- 서로 다른 기준일의 **측정값**(총보수·수익률·기간말 잔고) 직접 비교; 투자설명서가 명시한
  분류값(위험등급·상품분류·판매 클래스)은 기준일과 함께 밝히면 비교할 수 있다
- 주최 측 원본 또는 파생 코퍼스 수정
- shell, 파일쓰기, 이메일, 메신저, 브라우저 자동화 도구 노출
- 문서 안의 명령이나 질문의 prompt injection 실행
- 시스템 프롬프트, API key, 인증 헤더, 원시 reasoning, 내부 예외 노출

## 3. 데이터 접근 범위

| 자원 | 접근 | 비고 |
|---|---|---|
| `data/knowledge/` | 읽기 전용 | 검증된 manifest와 일치해야 함 |
| `data/structured/` | 읽기 전용 | 상품 100레코드와 corpus hash 확인 |
| 제공받은 원본 자료 | 런타임 직접 접근 금지 | 전처리 도구만 read-only 접근 |
| `agents/prompts/` | 시작 시 읽기 전용 | hash가 cache identity에 포함됨 |
| `data/runtime/` | 캐시 쓰기 허용 | 질문 원문 포함 응답의 보존정책 필요 |
| 외부 네트워크 | HCX endpoint만 | 운영 egress allowlist 권장 |
| `docs/` | 런타임 접근 금지 | 참고자료이며 운영 근거 아님 |

## 4. 신뢰 경계

- 신뢰 설정: 애플리케이션 코드, 검증된 운영 계약, 고정 시스템 프롬프트
- 조건부 신뢰: 해시가 일치하는 주최 측 파생자료
- 비신뢰 데이터: 사용자 질문, 문서 본문, 표 셀, 외부 backend 문자열
- 비밀: HCX credential, 환경변수, 인증 헤더, 내부 프롬프트

비신뢰 데이터는 시스템 지시나 도구 호출 권한으로 해석하지 않는다.

## 5. 실패와 중단 기준

- 코퍼스/색인 hash 불일치: 시작 실패
- 필수 입력 누락: 정상 한계 응답
- 근거 없음 또는 충돌: 정상 한계 응답
- HCX timeout/network/5xx: 503 또는 504
- HCX schema·filter 실패: 502
- 전체 시간예산 부족: 새 도구 호출을 시작하지 않고 정해진 timeout 처리
- 캐시 write 실패: 응답 일관성 정책을 정한 뒤 구현; 현재는 기술 실패 가능성으로 테스트 필요

## 6. 변경 권한

운영 Agent는 자신의 코드·프롬프트·스킬·코퍼스를 수정하지 않는다. 개발 Agent가 변경하더라도
테스트, 검토, 릴리스 manifest를 거쳐야 한다. 제출 마감 뒤에는 재기동 외의 결과물 변경을 하지
않는다.
